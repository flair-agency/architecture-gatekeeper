# Offline verifier descriptor-read reuse

Baseline is normally adopted #617 `8743549e309b6516328bedd30975ae0f44f89b08`; its runtime/script bytes match #616. This is partial #573 implementation, not historical BLOCK acceptance or whole-issue completion.

This change reuses the emitted `readDescriptorBytes` helper in the private CLI's bounded file reader. It removes the local read loop while retaining the caller's file checks, exact-size buffer, length requirement, descriptor ownership, and downstream decoder.

| Risk / invariant | Production boundary | Retained oracle and limit |
| --- | --- | --- |
| A positive short read must be accumulated to the `fstat` size. | The actual private CLI reader handles both the trusted expected-identity file and review-record file. | The focused child test injects deterministic two-byte reads, checks multiple positive reads per input, exact byte totals, descriptor closes, and exact bytes frozen for the record. The first `gh attestation verify` invocation is intercepted and stopped before dispatch. |
| Early EOF must remain an incomplete read, and read failures must still close the descriptor. | `readFileBounded` retains the initial regular-file/nonempty/maximum-size checks and compares the helper's returned length to the original `stat.size`; its `finally` still closes the descriptor. | Focused cases inject early EOF and a read exception separately for each input and check the verifier error plus close order. These are ordinary temporary files and deterministic I/O shims. |
| Fatal UTF-8 decoding must happen after close. | `parseJson` still decodes only after `readFileBounded` returns. | A malformed expected-identity fixture records that the selected bytes reached the real fatal decoder after close, checks the UTF-8 failure, and confirms record reading and child dispatch did not occur. |
| The external boundary must remain bounded and unexecuted in this test. | CLI reaches its first existing `execFileSync('gh', ...)` only after reading both inputs and writing the frozen record. | The test preload validates the exact `gh attestation verify` arguments, existing timeout/output limit, closed/read inputs, and owned temporary path before inspecting frozen bytes; it then throws a sentinel. Unexpected `execFileSync` calls are stopped before reading an argv path. The preload also replaces global `fetch`. The local focused invocation uses a PID- and network-isolated namespace; that is a property of the recorded invocation, not a requirement or property of every CI test run. This does not claim generic process or socket isolation. |

The shared helper advances the descriptor's current position with `position=null`, whereas the removed loop supplied an explicit offset. Here `readFileBounded` opens a fresh private descriptor, has no consumer of its intermediate position, and closes it immediately after reading. This is a local call-site assumption, not a general byte-equivalence claim.

The exact `Buffer.alloc(stat.size)` remains in the caller. If a file grows after `fstat`, the helper cannot read beyond that initial allocation; if it shrinks or ends early, the returned-length comparison preserves the existing `changed during read` failure. The stat preconditions and fatal decoder ordering are unchanged.

The focused child tests use synthetic ordinary files and stop before real `gh`, Git, attestation verification, API access, or a live host. They establish neither live provenance nor policy acceptance, and make no security or host-proof claim. The earlier external harness iteration failures and their correction remain recorded with the proposal review artifacts; they are not source-checkout test results.

The import names `../dist/io/read-descriptor.mjs`, consistently with this script’s existing emitted imports; it introduces no TypeScript source-loading requirement. The script and these tests are repository-only, outside the installed package file set. No public export, caller-selected output, environment injection, authority, policy or acceptance route changes.

The [handoff adapter comparison](https://github.com/flair-agency/architecture-gatekeeper/issues/573#issuecomment-6249500815) retains its two short adapters, and the [exact-version library evaluation](https://github.com/flair-agency/architecture-gatekeeper/issues/573#issuecomment-6249625541) retains Node standard APIs / Git CLI. These engineering dispositions and this narrow loop reuse do not authorize the separately proposed native responsibility transfer or establish live consumer/lifecycle proof.
