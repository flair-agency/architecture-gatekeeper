# Issue #83: next probe for a historical PR `BLOCK`

Status: experiment design only. The merged synthetic producer probe proves that a protected workflow can attest a completed, deterministically validated Codex `BLOCK`. It does not yet produce evidence about a real pull request. This plan targets this public first-user repository and its current self Authority Set; external-source and private-repository coverage remain separate validation work. The next probe stays outside `Architecture Gate / accept` and does not enable `OWNER_AMENDMENT`.

## Claim to test

For a real PR, an independent verifier should be able to say: these exact ReviewRecord bytes came from the protected Gatekeeper workflow at a specific source commit and run attempt, after that workflow reviewed a particular merge revision against the protected base's selected Authority Set and validated a `BLOCK`. The attestation certificate can authenticate the bytes, signer workflow, source commit and run attempt. It does **not** expose a job ID; the reviewed decision and protected inputs must be bound by the reviewed workflow's execution structure and independently checked record contents.

## Minimal test-only route

1. Use a dedicated `pull_request_target` workflow from protected `main`, triggered only for an explicitly selected test PR. Do not use `workflow_dispatch` with a selectable PR-branch workflow. The PR checkout is review evidence; the workflow, validation runtime, policy, prompt, schema, manifest and same-repository Authority bytes come from the protected base or pinned Gatekeeper runtime. Do not execute PR package scripts.
2. Run the existing pinned Codex Action integrity check before the model job receives `OPENAI_API_KEY`. The model job has `contents: read`, no OIDC or attestation permission, and the same read-only Action options and five-minute step limit as the self gate. Record the exact repository, PR number, base SHA, head SHA and checked-out merge SHA. Require the merge commit's parents to be the recorded base and head before treating it as that PR's reviewed revision.
3. Materialize the complete Authority Set and prompt using the current protected CI route. Transfer the exact decision bytes and bounded Authority provenance through a run-and-attempt-named artifact. A missing current-attempt artifact fails closed, as the producer-only rerun of run 36100963659 already demonstrated.
4. In a separate producer job, with no model or source-read secret, independently obtain the protected base inputs and the current-attempt decision artifact. Re-run schema, consumer decision rules and complete Authority ID validation; require top-level `BLOCK`. Verify the PR/base/head/merge relationship and the selected Authority Set and input digests before serializing a versioned **test-only** ReviewRecord. A successful report comment, job status or decision JSON field is not sufficient validation.
5. Attest the exact record bytes from the protected producer and retain a copy for separate verification. The producer has only the permissions required to read the repository, request OIDC and write the attestation. Its output must not be wired to the required acceptance check.

The first test PR should make a narrow, unambiguous proposal that conflicts with the protected fail-closed rule, while remaining a draft, non-mergeable fixture. The existing self gate and the test workflow should independently report `BLOCK` for that exact head. If the model instead returns `PASS`, `OWNER_DECISION`, malformed output or no output, the test route must produce no ReviewRecord or attestation; do not coerce the decision to make the probe pass.

## Independent verification and failure cases

The verifier starts with expected repository, PR, base/head, signer workflow, source commit and run attempt from a trusted request or protected policy. It downloads the exact record bytes, verifies the attestation signature and subject digest, constrains the signer workflow, and compares the certificate's run/attempt with the expected execution. It then validates the record format, decision and digests and fetches the referenced Git objects and protected inputs independently. Record fields and artifact names remain claims until these checks finish.

Demonstrate a complete historical `BLOCK`, then show rejection or incompleteness for changed head/base, substituted or edited record, wrong signer, wrong attempt, missing current-attempt decision, incomplete model review, and deleted/expired record bytes. Distinguish live GitHub observations from local fixture tests. A full rerun may create another valid historical record for its own attempt; it must not silently replace the identity of an earlier attempt. A producer-only rerun must not consume an earlier attempt's decision.

The initial seven-day artifact setting is enough for a short-lived probe, not for #78's historical evidence. Before a production route is enabled, choose durable storage and read permissions for the exact bytes and verify that the intended first-user repository can fetch them after artifact expiry or reruns. The GitHub attestation feature's private/internal availability must also be checked for each supported consumer class. If either property is absent, report `INCOMPLETE` and keep G0 acceptance disabled.

## Decision after the probe

If the live real-PR experiment establishes the binding above, #83 can report that the GitHub attestation route is technically viable for the public first-user repository, with the missing certificate job ID compensated by protected workflow sequencing. #78 then still needs a separately reviewed production ReviewRecord contract, durable evidence retrieval, exact protected-policy selection and a fresh-current-state verifier. If the binding cannot be established, #83 should identify the failed trust claim and an alternative producer trust source instead of accepting run-level artifact metadata.
